## 2025-07-22 - Supabase count='exact' API N+1 Optimization
**Learning:** PostgREST (which Supabase uses) correctly calculates the total count for paginated lists using `count='exact'` within the primary `select` query, without needing a secondary database call. The `count` parameter calculates based on the applied filters before `range` limits are applied. A redundant second query just for `count` creates a performance bottleneck (N+1 query problem).
**Action:** When implementing pagination with the Supabase client, append `count='exact'` to the primary `select('*')` query to retrieve both paginated records and the total row count in a single database round-trip. This avoids redundant queries. Access the count via `result.count if hasattr(result, 'count') and result.count is not None else len(result.data)`.
