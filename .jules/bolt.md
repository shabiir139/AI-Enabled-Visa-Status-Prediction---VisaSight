## 2025-03-05 - FastAPI Synchronous Blocking & Pagination Query Optimization
**Learning:** The backend utilizes the synchronous `supabase` Python client and CPU-bound ML predictors within `async def` FastAPI route handlers. This creates a severe performance bottleneck because synchronous operations block the main event loop, preventing concurrent request handling. Additionally, pagination queries currently use a two-step process (fetching data then fetching the count separately), which introduces an N+1 style inefficiency.
**Action:** Always use `def` instead of `async def` for FastAPI endpoints that execute synchronous, blocking operations (like Supabase client calls or CPU-bound ML tasks) to offload execution to a thread pool. For Supabase pagination queries, utilize `.select('*', count='exact')` to retrieve both data and the total count in a single request, eliminating the need for a separate count query.
