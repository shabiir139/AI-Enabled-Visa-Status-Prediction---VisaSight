## 2026-02-10 - Supabase Exact Count Pagination Optimization
**Learning:** In Supabase, retrieving paginated items and the total count separately creates a classic N+1 (2 for 1) redundant query pattern. Using `select("*", count="exact")` allows PostgREST to return the total unpaginated row count in the response headers (parsed as `result.count` by the Python client) alongside the paginated data, effectively halving the required database round-trips for pagination endpoints. Attempting to blindly replace single quotes globally in Next.js JSX via regex to fix unescaped entity lints (`&apos;`) is destructive and introduces fatal syntax errors.
**Action:** Always prefer `select("*", count="exact")` for any paginated endpoint querying Supabase to optimize database performance. Fix JSX unescaped entity lint warnings manually or specifically target text nodes only, never JavaScript strings or logic blocks.
