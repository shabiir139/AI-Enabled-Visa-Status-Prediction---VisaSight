## 2024-05-18 - [Supabase Query Optimization & Synchronous Blocking]
**Learning:** In FastAPI, using `async def` for a route handler that calls synchronous code (like the `supabase-py` client) blocks the main asyncio event loop, causing severe latency for all other concurrent requests. Also, the Supabase Python client's `.select("*", count="exact")` correctly returns both the result data and the count on the same response object (`result.count` and `result.data`), making separate `.select("id", count="exact")` queries completely redundant and unnecessary double round-trips to the database.
**Action:** When building pagination or count queries with Supabase, always use `.select("*", count="exact")` to grab everything in a single roundtrip. When a handler relies on synchronous blocking logic or clients, strictly define it with `def` (instead of `async def`) so that FastAPI correctly assigns it to an external thread pool, preserving the main event loop's concurrency.
