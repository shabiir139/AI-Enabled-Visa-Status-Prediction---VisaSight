## 2025-02-18 - Supabase Pagination Redundant Database Queries
**Learning:** In the backend `cases.py` and `rules.py` routes, I noticed an N+1 or redundant fetching pattern where a `select("*")` query is executed first, followed by an identical query specifically calculating `count="exact"`. This is highly inefficient because it requires a whole additional network roundtrip to the Supabase database just to fetch pagination metadata (the total count).
**Action:** When working with Supabase Python client pagination, optimize the primary `.select()` fetching operation by directly appending `count='exact'` (e.g., `supabase.table("visa_cases").select("*", count="exact")`). PostgREST handles calculating this exact row count in the same single round-trip, ignoring any range modifiers, and the result can be extracted using `result.count if hasattr(result, 'count') and result.count is not None else len(result.data)`.
