## 2025-05-15 - [Supabase Python Client N+1 Query Fix]
**Learning:** The Supabase Python client's `.select()` method natively supports returning a count alongside paginated data by passing the `count="exact"` parameter (e.g., `.select("*", count="exact")`). Before this optimization, developers were manually querying for data and then running a completely separate `.select("id", count="exact")` query just to get the total number of rows. This caused an unnecessary database round-trip (N+1 query pattern) for every paginated API endpoint, effectively doubling the database load. Furthermore, checking for `hasattr(result, 'count')` and `result.count is not None` is safer when parsing the result object, as zero is falsy.
**Action:** When implementing pagination with the Supabase Python client, always combine the data fetch and count into a single query using `.select("*", count="exact")` to minimize network latency and database hits. Avoid separate count queries unless complex filtering requires it.
