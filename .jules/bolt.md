## 2025-02-09 - [FastAPI Event Loop Blockage with Sync Supabase Client]
**Learning:** Found a critical performance bottleneck where asynchronous FastAPI endpoints (`async def`) were executing synchronous operations (specifically, blocking `supabase-py` client calls and CPU-bound ML model inferences). This causes the main ASGI event loop to block, completely stalling the backend service under load. Furthermore, pagination queries were performing redundant `.select("id", count="exact")` queries after fetching data.
**Action:** When using synchronous dependencies (like the `supabase` Python client or `scikit-learn`/`transformers` models) in FastAPI, always define the route handlers with `def` rather than `async def`. FastAPI will then automatically execute these handlers in an external thread pool, preventing them from blocking the main event loop. For Supabase pagination, combine data fetching and counting into a single query using `.select("*", count="exact")` to avoid N+1 database roundtrips.
