## 2026-07-04 - Supabase Pagination Count N+1 Query
**Learning:** Found redundant N+1 query patterns in `backend/app/api/cases.py` and `backend/app/api/rules.py` where a `select('*')` query was followed by a separate `select("id", count="exact")` query to get the total count for pagination. The Supabase Python client can retrieve both paginated records and the total row count in a single database round-trip by appending `count='exact'` to the primary `select('*')` query, preventing N+1 queries. PostgREST accurately calculates the total based on filters and ignores pagination modifiers.
**Action:** When implementing pagination with the Supabase client, combine the data and count fetch into a single query by appending `count='exact'` to the main `select` call and accessing the result's `.data` and `.count` attributes.
