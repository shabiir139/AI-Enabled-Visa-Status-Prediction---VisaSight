## 2024-05-19 - N+1 Supabase Pagination
**Learning:** Found an N+1 query problem in the pagination logic for `list_visa_cases` in `backend/app/api/cases.py`. It first performs a query to get the paginated records, and then immediately performs a second query just to get the total count (`supabase.table("visa_cases").select("id", count="exact")`). According to the memory, "When implementing pagination with the Supabase client, append `count='exact'` to the primary `select('*')` query to retrieve both paginated records and the total row count in a single database round-trip, avoiding redundant N+1 queries. PostgREST correctly calculates this based on filters while ignoring range/limit modifiers."
**Action:** Optimize `list_visa_cases` to fetch both data and count in a single round-trip by appending `count='exact'` to the main query.
