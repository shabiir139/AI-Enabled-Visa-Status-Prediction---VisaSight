## 2024-05-18 - Single Query Pagination in Supabase
**Learning:** The application is suffering from N+1 query problems in its pagination logic. In both `cases.py` and `rules.py`, the backend currently executes two separate database queries for paginated endpoints: one query to fetch the limited page of results (`select("*").limit().offset()`), and a second query to get the total count for pagination math (`select("id", count="exact")`). This doubles the database round-trips for list endpoints.
**Action:** When implementing pagination with the Supabase client, we should append `count='exact'` to the primary `select('*')` query to retrieve both paginated records and the total row count in a single database round-trip. This avoids redundant N+1 queries. PostgREST correctly calculates the total count based on applied filters while ignoring range/limit modifiers in the same query.
