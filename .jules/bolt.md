## 2026-03-19 - N+1 Query Elimination in Supabase Pagination
**Learning:** The synchronous `supabase-python` client `execute()` method returns a response object with a `count` property when querying with `count='exact'`. Making a separate `.select("id", count="exact")` query for pagination is redundant and creates a significant backend performance bottleneck by doubling database network roundtrips per request. Additionally, calling synchronous database logic inside `async def` endpoints blocks FastAPI's main event loop, severely limiting concurrency.
**Action:** When performing pagination with Supabase in FastAPI, use `.select('*', count='exact')` to retrieve data and total count simultaneously, extracting the total from `result.count`. Further, always declare endpoints doing synchronous I/O or ML inference with `def` rather than `async def` to ensure they are offloaded to an external thread pool by FastAPI.
