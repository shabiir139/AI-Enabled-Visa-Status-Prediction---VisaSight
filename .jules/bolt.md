## 2026-10-03 - [Supabase Python Client N+1 Query Elimination]
**Learning:** In Supabase's Python client, when implementing pagination, fetching the `total` rows via a separate `.select("id", count="exact")` query introduces an unnecessary N+1 round-trip. This can be eliminated by modifying the main `.select("*")` query to include `count="exact"`. PostgREST will then return both the paginated data (respecting the `.range()` modifier) and the total matched rows in a single DB round-trip. The count is accessible via `result.count` (but requires defensive checking since it may be `None` or absent depending on the client version).
**Action:** Always append `count="exact"` to the primary `.select()` when paginated lists and row counts are required simultaneously, and extract the total directly from the main query's result rather than issuing a second separate counting query.
